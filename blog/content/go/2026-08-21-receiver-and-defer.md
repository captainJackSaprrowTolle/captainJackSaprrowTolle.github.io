在阅读标准库 `time.go` 源码时，顺便深入研究了一下 Go 的设计哲学。

## 没有 class：用组合和接口代替继承

Go 没有 class，不靠继承实现复用，这点和 Java、C++ 不同。用 struct 代替 class，是为了规避继承的弊端：改基类方法容易牵连子类，为复用某个方法又得搭出一层层继承关系。

## receiver：给类型绑定方法

```go
func (t Time) Xxx()
```

给函数加一个 receiver，它就成了某个类型的方法——Go 里叫**给类型绑定方法**。上面这行是给 `Time` 类型绑定了一个 `Xxx` 方法，很灵活。

为什么叫 receiver：类似"给某个对象发消息"的范式（大概是 Smalltalk 一路的思路，没细考证），receiver 就是接收消息的对象。

Go 没有 `abstract` 关键字，也没有抽象类；方法签名只能靠 interface 声明，不用像 Java 那样另搞一套抽象方法语法。

## struct / interface / func 是平铺关系，不是嵌套

三者是平的，不是一层套一层：

- **interface**：规定"要会做什么"，不管是谁做、怎么做。
- **struct**：一个具体的类型，比如"狗"。
- **func**：具体怎么做的代码；绑定到某个类型上，就是这个类型"会做的事"。

比如 interface 规定"要会叫"，struct 是"狗"，func 写的是"汪汪"这段代码。狗只要把"叫"这个 func 写出来了，就自动算"会叫的东西"，不用专门声明。

## 值接收者 vs 指针接收者

变量可取地址（addressable）时，Go 会自动转换：用值调用指针接收者方法、或用指针调用值接收者方法都可以，不用手动加 `&` 或 `*`。

真正的区别在方法集：指针类型的方法集包含值接收者和指针接收者两种方法，值类型只包含值接收者方法。所以通过 interface 调用时，如果某方法只在指针接收者上实现，值类型就满足不了这个 interface，必须传指针。

`*p` 和 `&v` 是一对互逆操作：`*p` 从地址取出对象，`&v` 取对象的地址。

## defer：栈结构，先进后出

defer 是栈结构，后进先出，在函数返回前自动执行——即使已经 `return`，该执行的 defer 照样执行。

常用来关闭文件资源，也可以用来让某段代码故意最后执行。
