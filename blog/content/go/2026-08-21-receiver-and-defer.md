在阅读标准库 `time.go` 源码时，顺便深入研究了一下 Go 的设计哲学。

## 没有 class：用组合和接口代替继承

Go 里没有传统编程语言的 class 这种东西，不像 Java、C++ 那种面向对象（OOP）语言里类、继承、封装的那一套。Go 用 struct 替代 class，是为了规避 OOP 继承带来的弊端：

- 改变基类的某个方法，子类可能就出问题了。
- 为了复用基类的某个方法，不得不造出一层层的继承关系。

## receiver：给类型绑定方法

```go
func (t Time) Xxx()
```

任何模块的任何方法，只要加一个 receiver，就能实现类似"给类型添加方法"的效果——Go 里管这个叫**给类型绑定方法**。上面这行代码的意思就是给 `Time` 类型加一个 `Xxx` 方法，非常灵活。

至于为什么叫 receiver：这类似于"发消息给某个对象"的编程范式（大概类似 Smalltalk 的思路，具体没考证过），receiver 就是"接收消息"的那个对象。

好消息是，Go 连抽象方法都不存在，好样的！

## struct / interface / func 是平铺关系，不是嵌套

三者彼此平铺，不是层层嵌套，这一点很好：

```
struct:     调用方 request  帮我准备 A 的午餐，并通知他吃饭
                    │
interface:  工具人 call    吃饭的通知：确认下是叫谁，怎么叫
                    │
func:       找到了 A 哥的午餐说明 run：A 哥吃午餐要吃鸡肉
```

## 值接收者 vs 指针接收者

调用时传指针（`&类型名`）→ 对应指针类型 receiver：`*接收者的类型名`

调用时传值（`类型名`）→ 对应值类型 receiver：`接收者的类型名`

`*p` 和 `&v` 是一对互逆操作：`*p` 是从地址返回对象，`&v` 是制作对象的地址。

## defer：栈结构，先进后出

defer 是一个栈结构，先进后出。函数结束前自动执行，即使函数已经走了 `return`，也照样会被执行，defer 不受影响。

常用在关闭文件资源，也可以用在故意想让某段代码最后执行的场景。
